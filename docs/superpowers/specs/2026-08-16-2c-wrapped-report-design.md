# 2C Wrapped（`report.html`）— 设计 spec

> 状态：设计已定，待 Codex 架构审 → 实现
> 上游：2B spec §5（`insights.json` 合同）/ 2D spec（档案线，已合并）
> 相关：DESIGN §4.1（双输出与裁决权）/ §4.2（Wrapped 是档案的验收界面）/ §5（L1 不做主角）/
> §7（脱敏双产物）/ §9 R12 R13 / §10（v0.1 验收标准）

## 1. 这是什么，以及它为什么不是「另一个输出」

`report.private.html` / `report.share.html` —— README 承诺的第二样门面产物。

但 2C 的真正职责不是「再产一个好看的文件」。DESIGN §4.2 立论的是一个**闭环**：

```
中间知识表示
   ├→ [Wrapped 渲染] → 人看 → 逐条确认/否决
   └→ [档案渲染] ←──────────┘  只收人确认过的
```

**2D 合并之后，这个闭环仍然是断的**：档案有了，操作层（`insights.md`）有了，
**呈现层没有**。而整套设计的立论正是「人凭什么愿意逐条校对一份枯燥配置文件？
因为它被渲染成了一份关于自己的、好玩的报告」。没有呈现层，人肉 gate 就只剩
一份枯燥配置文件——那正是这份设计当初判定**行不通**的东西。

所以 2C 的验收问的不是「好不好看」，而是**「它能不能让人真的把 15 条洞察逐条看完」**。

## 2. 开工前的两个实测发现

### 2.1 呈现层与操作层之间没有桥

看真实产出的 `insights.md`：每条带 `T1` / `R1` / `C1` 这样的可见短 ID。
而报告若不印同一个 ID，用户看完报告回到清单**找不到对应哪一条**——
两层各说各话，闭环在人的那一步断掉。

> **报告的每一条必须印出与清单相同的短 ID。** 这不是装饰，是这两层唯一的接缝。

### 2.2 时序：分享版不能在主 run 时生成

| 命令 | 时点 | 用户审过了吗 |
|---|---|---|
| `kb-init <source>` | 产出 `insights.md` + 报告 | **没有**——报告正是给他审的东西 |
| `kb-init compile` | 产出档案 | 审过了 |

`report.share.html` 是**要发出去**的（§10.1「看完想转发」）。在主 run 时生成它，
等于把用户**还没审过**的内容直接做成了分享品——而这份语料里真实出现过账号 handle
（`examplehandle1` / `examplehandle2` 之类）被抽成关键词的情况。

**裁决：私有版在主 run 生成，分享版在 `compile` 生成。**

- `report.private.html`（run）—— 全量，给自己看，它就是那个验收界面；
- `report.share.html`（compile）—— **只含用户勾选过的条目** ∩ 字段 allowlist。

这条同时让勾选框的语义变完整：**勾一条 = 我认可它 = 它可以进档案、也可以被我发出去。**
不新增第二种勾选框——那会把人肉 gate 的行数翻倍，直接撞上 12–20 条的疲劳线。

## 3. 文案归谁：Wrapped **逐字**显示 `canonical_text`

这是 2D 遗留的那个问题（「档案正文是审阅用语，读起来不像档案」），在 2C 一并裁掉。

**若报告的文案与最终进档案的文案不同，用户就是在用文案 A 做决定、而档案里进的是文案 B**
——那正是 2B 双载合同要防的病，只是这次换成了「呈现层 vs 真源」这一对。
2D 已经为档案线付过这笔代价，2C 没有理由再开一个渲染器。

因此：

- 报告每条的**断言性文字** = `canonical_text`，逐字；
- 报告可以自由地做**排版**：关键词做成大号 chip、篇数做成从零起算的条形、
  分节、留白、配色；
- 允许把 `payload` 里的字段**原样另行陈列**（关键词、篇数、证据标题），
  因为那是同一批已被 `canonical_text` 陈述过的事实换个位置显示，不是新断言；
- **不允许**任何生成式文案：「你今年最痴迷的是 X」「你的知识库很健康」一律不写。

> **「好玩」由排版承担，不由文案承担。** 这条一旦松口，2C 就会长出一个
> 「Wrapped 文案生成器」，而它每次升级都会让用户审过的东西和看到的东西错位。
> 顺带回答 2D 的遗留问题：**`canonical_text` 不改**——它的任务是「好审」，
> 报告的任务是「好看」，两者由不同的层承担，不必挤在一句话里。

## 4. 报告长什么样

单文件、自包含、无 JS、无外链（§7「静态文件不是服务」；§10.1「能双击打开、无需联网」）。

```
┌──────────────────────────────────────┐
│  你的知识库                            │
│  620 → 287                            │  ← 大字，来自 retention 的 payload
│  这份报告由 kb-init 生成，run 952c3d…  │
├──────────────────────────────────────┤
│  ## 主题                              │
│  ┌────────────────────────────────┐  │
│  │ T1  vocabolo verbo parola nome │  │  ← ID + 关键词 chip
│  │ ████████████████░░░░░  32 篇   │  │  ← 从零起算的条形
│  │ 这 32 篇里最具区分度的词是 …    │  │  ← canonical_text 逐字
│  │ 证据：〈标题〉·〈标题〉·〈标题〉  │  │
│  └────────────────────────────────┘  │
│  ## 碎片区 / ## 语料                  │
├──────────────────────────────────────┤
│  下一步：打开 insights.md，取消勾选你  │
│  不认可的条目，然后跑 kb-init compile  │
└──────────────────────────────────────┘
```

**条形的比例必须从零起算**，不许截断坐标轴——一条被截断的柱子是在撒谎（硬不变量 #4）。

**收尾那段「下一步」是必须的**：报告是验收界面，看完不知道该干什么，闭环照样断。

## 5. 分享版：allowlist 是字段级的，且必须承认它不够

DESIGN §7 已裁决：「默认脱敏 + PII 正则」制造虚假安全感，blocklist 永远补不完，
allowlist 一次收敛。所以分享版的实现是**从零开始只放行列出的字段**，
而不是「拿私有版删掉几处」。

| 字段 | 私有版 | 分享版 | 理由 |
|---|---|---|---|
| 篇数 / 占比 / 留存率 / 中位数等纯数字 | ✅ | ✅ | 不含内容 |
| `insight_id`、族别、节标题 | ✅ | ✅ | 结构 |
| `canonical_text` | ✅ | ✅ | 它由数字与关键词构成，不含标题与路径 |
| `keywords` | ✅ | ✅ | 报告的全部内容价值所在；去掉就没人会转发（见下） |
| `evidence_titles` | ✅ | ❌ | **真实笔记标题**，最直接的身份泄露 |
| `evidence_doc_ids` / 路径 / 文件名 | ✅ | ❌ | 同上 |
| `run_id` / `corpus_hash` | ✅ | ❌ | 与本机产物可关联 |
| `naming.params` / `limits` / `revisit_gate` | ✅ | ❌ | 项目自己的收据，与读者无关 |

**必须写明的一条**：字段级 allowlist 挡不住**值**级泄露——关键词本身就来自正文，
真实语料里就出现过账号 handle 被抽成关键词。因此分享版必须做两件事：

1. **只收用户勾选过的条目**（§2.2）——这是唯一真正有效的 gate，因为只有人能判断；
2. 在**文件里可见地**声明它包含什么、不包含什么，并在 CLI 输出里**把分享版包含的
   全部关键词打印出来**，让用户在发出去之前肉眼过一遍。

> 不做「PII 正则兜底」。它会制造「工具已经帮我脱敏了」的错觉，而这个错觉比没有脱敏更危险
> ——这与我们在 headless 权限上学到的是同一课。

## 6. XSS：语料内容进 HTML 是真实攻击面（R13）

关键词与证据标题**全部来自用户语料**，而开源工具接受任意导出包。
一篇标题为 `<script>alert(1)</script>` 的笔记会直接把脚本写进报告。

三道防线，都不是可选项：

1. **所有插值一律 HTML 转义**（`&<>"'`），且转义发生在**唯一一处**——
   模板里不允许出现未经该函数的插值；
2. **报告不含任何 `<script>`、不含任何外链**（无 CDN 字体、无远程图片）；
3. `<meta http-equiv="Content-Security-Policy" content="default-src 'none'; style-src 'unsafe-inline'; form-action 'none'; base-uri 'none'">`
   —— 纵深防御。`form-action` / `base-uri` 不是多余的：转义一旦失守，**不用 JS 也能外送**
   （注入一个 `<form action=...>` 或改 `<base href>`），而 `default-src` 管不到这两个。

**第四条，属于 CSS 上下文**：HTML 转义**不保护 CSS 语法**。报告里唯一进入 CSS 的值是
条形的宽度百分比，它必须：

- 由 `payload` 的数字算出，**不接受任何字符串插值**；
- 钳位到 `[0, 100]` 并以固定格式输出（`f"{value:.1f}"`），非有限值（NaN / inf）一律
  当作合同违例报错，不静默取 0——取 0 是猜。

模板里除了这一个数字，**没有任何值进入 `style` 属性**。这条比「小心一点」有用，
因为它是可测的。

**测试必须配负例**：一条「转义函数被摘掉就会红」的断言，以及一条正例
（正常内容不被过度转义成乱码）。§10.7 明确要求 `<script>` 这一项各测一次。

## 7. 失败处理

**报告失败不许带走已完成的产物**（硬不变量 #2）——沿用 2A/2B 已确立的形态：

| 场景 | 处置 | 退出码 |
|---|---|---|
| 主 run 里私有版渲染/写盘失败 | 清洗 + 索引 + 洞察全部保留，`manifest.report_status = "failed"` | **10** |
| `compile` 里分享版失败 | 见下 | 4 |

退出码 10 与 5 / 6 是同一族：**恢复动作不同就分开**——5 要重跑索引（要网络与模型），
6 只差洞察，10 只差报告。

### 7.1 私有版：写进 staging，原子性是白送的

主 run 的私有版**写进 staging 目录**，随最后那一次 `staging.rename(out_dir)` 一起发布。
于是它不需要任何 tmp / replace 逻辑——「整次运行原子」这条已有的机制直接覆盖它。

阶段函数照抄 `_run_insights_stage` 的形状，一个字都不改动它的纪律：

- 位置在洞察阶段之后、最终 `write_manifest` 之前；
- **失败必须在阶段函数内被吸收成状态，绝不允许异常放出去**——放出去会穿到
  `run()` 的 `finally`，把清洗产物、索引、洞察**一起删掉**。2A 与 2B 各埋过一次这个洞；
- 清理半份产物的路径同样不许抛；清不掉就把 `report_reason` 记成 `io_failed`，
  由 manifest 兜住「这份文件不算数」。

`report_status` 取值与 `insights_status` 对齐：

| 值 | 何时 | reason |
|---|---|---|
| `complete` | 报告已写进 staging | `null` |
| `skipped` | 没有洞察可渲染 | `no_index` / `index_failed` / `insights_failed` |
| `failed` | 渲染或写盘失败 | `render_failed` / `io_failed` |

**只有 `failed` 才返回退出码 10。** `skipped` 不是失败——`--no-index` 本来就没有洞察，
给它报个错等于说「你用错了」，而那是一条一等公民的通道。

### 7.2 分享版：它不需要覆盖授权

2D 为档案建了一整套授权机制（回执 + 哈希 + 拒符号链接），是因为档案落在
`knowledge/` 里——**那个目录装着用户的笔记**，完全可能真有一篇叫 `CLAUDE.md`。

`report.share.html` 落在 **`out_dir` 根目录**，而那里 100% 是工具自有产物
（`index.json` / `insights.json` / `manifest.json` / `compile.json`）：语料笔记只会被
清洗进 `knowledge/`，且 `out_dir` 非空时主 run 直接拒绝运行（退出码 1）。
**碰撞面根本不存在，所以不给它套授权**——为一个不存在的风险加机制，
本身就是一种谎。

由此 compile 的顺序保持简单，**2D 的实现一行不改**：

```
渲染档案与分享版（纯内存，渲染失败时一个字节都还没落）
  → publish(档案)     ← 2D 原样：取锁 / 授权 / 原子替换 / 写回执
  → 原子写分享版      ← tmp + os.replace，无授权
```

- **回执继续只描述档案**，不记 `share_sha256`。让一份回执描述两个文件，就必须回答
  「一个有主一个没主」怎么办；而分享版是**可重新生成的派生品**，它不需要有主。
- 分享版写失败 → 退出码 4，**档案与回执完好**。恢复动作就是重跑 `compile`：
  回执与档案对得上 ⇒ 授权通过 ⇒ 两个文件一起重新生成。**不会卡住**。

## 8. 架构

| 模块 | 职责 | 依赖 | 不认识 |
|---|---|---|---|
| `report.py`（新） | HTML 转义 + 模板 + 私有/分享两种视图的渲染（纯函数：payload → str） | 无 | 写盘、CLI、索引 |
| `claude_md.py`（改） | `publish` 扩展为同时发布档案与分享版，回执记两个哈希 | 同前 | 渲染细节 |
| `pipeline.py`（改） | 主 run 末尾产私有版，失败吸收成 `manifest.report_status` | `report` | HTML 细节 |
| `cli.py`（改） | 退出码 10；compile 侧打印分享版包含的关键词 | — | — |

**沿用「每一层的写盘集中在一处」**：报告的 HTML 由 `report.py` 生成但**不由它写盘**——
私有版由 `pipeline.py` 写（与索引、洞察同一条事务线），分享版由 `claude_md.py` 写
（与档案同一次授权、同一把锁、同一份回执）。让渲染器碰磁盘，就会出现第二套原子性实现。

## 9. 明确不做

| 不做 | 理由 |
|---|---|
| 任何 JS / 交互 / 服务 | §7 硬边界。静态文件能直接发给别人看，而「能发给别人看」正是传播的定义 |
| 生成式文案（「你今年最痴迷的是…」） | §3：文案错位会让用户审过的与看到的不是一回事 |
| PII 正则兜底脱敏 | §5：制造虚假安全感 |
| 时间轴图表 | `time_axis.available == false`，画不出来又不能假装 |
| 让报告自己决定显示哪几条 | 呈现层不做筛选：清单有几条，报告就有几条，否则用户会以为清单里那条是多出来的 |
| 分享版加水印 / 二维码 / 品牌页 | 传播设计，不是 v0.1 的题；且会诱导把 run_id 之类塞回去 |

## 10. 测试策略

| 测试名 | 断言 |
|---|---|
| `test_every_insight_appears_with_its_id` | 清单里每条的短 ID 都出现在报告里（呈现层与操作层的接缝） |
| `test_assertive_text_is_canonical_verbatim` | 每条的 `canonical_text` 逐字出现 |
| `test_report_contains_no_generated_prose` | 报告里除模板常量外，不含任何不能追溯到 payload 的断言句（同 2D 的「一行都不能多」思路，用计数比对） |
| `test_script_tag_in_title_is_escaped` | 标题含 `<script>` → 报告里不出现可执行标签，出现的是转义实体 |
| `test_normal_text_is_not_over_escaped` | 负例的配对正例：正常中文/英文不被转义成乱码 |
| `test_no_reference_constructs` | 报告里不含 `src=` / `href=` / `<script` / `@import` / `url(`。**判据是「制造引用的构造」而不是子串 `http`**——真实语料的证据标题里就含裸 URL，扫 `http` 会与「canonical_text 逐字显示」直接冲突，且那种 URL 只是被转义的文本，点不开 |
| `test_bare_url_in_title_is_not_linkified` | 证据标题含裸 URL → 报告里它是纯文本，没有被自动变成链接 |
| `test_bar_width_is_clamped_and_fixed_format` | 条形宽度只接受数字、钳位 0–100、固定小数位；NaN / inf → 报合同违例而不是静默取 0 |
| `test_csp_meta_present` | CSP meta 存在且 `default-src 'none'` |
| `test_share_omits_every_denied_field` | 参数化：证据标题 / doc_id / run_id / corpus_hash / naming.params 各自不出现在分享版里 |
| `test_share_keeps_allowed_fields` | 配对正例：关键词与数字仍在，否则「全删掉」也能让上一条全绿 |
| `test_share_only_contains_checked_items` | 取消勾选的条目不进分享版 |
| `test_bar_scale_starts_at_zero` | 最大条与次大条的宽度比 == 篇数比（截断坐标轴即红） |
| `test_report_failure_keeps_pipeline_products` | 私有版渲染抛错 → 清洗/索引/洞察产物**全部仍在**，退出码 10 |
| `test_report_cleanup_failure_still_does_not_raise` | 清理半份报告也失败 → 仍不抛，`report_reason == "io_failed"` |
| `test_report_skipped_is_not_an_error` | `--no-index` → `report_status == "skipped"`，退出码 **0** |
| `test_share_render_failure_writes_nothing` | 分享版**渲染**失败 → 档案与回执一个字节都没写（渲染在写盘之前） |
| `test_share_write_failure_keeps_archive_and_is_rerunnable` | 分享版**写盘**失败 → 退出码 4，档案与回执完好，**再跑一次 compile 能成功**（不卡住） |

**真实语料验收**（不进 CI）：两份语料各跑一遍完整链路，产出私有版与分享版，
落仓库外；人工打开看。

## 11. 验收标准

**合同层**（自动）：上表全部通过；全量 `pytest -q` 不退步（当前 417 passed + 5 smoke）。

**门面层**（人肉，与 2D 同一条纪律）：

1. 在真实语料上产出的 `report.private.html` 双击能开、无需联网；
2. **贾老师看完之后，能说出「我要取消勾选哪几条」**——这是这份报告唯一的功能测试。
   看完不知道该动哪条，说明呈现层没起作用，好看也没用；
3. `report.share.html` 拿给第三个人看，**看不出这是谁的知识库**（标题、路径、run_id 全无）；
4. 已知不达标项提前记账：Apple Notes 的前两条关键词是已声明的命名失效模式，
   报告会如实显示它们——**这正是人肉 gate 该发挥作用的地方**，不是报告的缺陷。

## 12. 风险

| 风险 | 处置 |
