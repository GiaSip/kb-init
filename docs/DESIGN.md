## 1. 一句话

把你攒了几年、自己都没再打开过的笔记导出文件，一次性编译成**两样东西**：一份你会想转发的知识报告，和一份你的 AI agent 从今天起就能用的记忆文件。

## 2. 为什么是这个（定位）

### 2.1 三块无人占的位置

2026-08-13 检索确认（单次检索 + README fetch，**正式动手前需真装验证**）：

| 层 | 现状 | 我们 |
|---|---|---|
| 格式转换 Notion→md | 红海：notion2obsidian / Notion-to-Obsidian-Converter / notion_2_obsidan / notion-markdown-extractor | **不写，直接调** |
| KB 管线 ingest / lint / retrieve | `AgriciDaniel/claude-obsidian` 10.8k★ MIT v2.1.0，同源于 Karpathy LLM Wiki，且带 BM25 检索、事务回滚、CI | **不做** |
| **冷启动批量导入** | 空（claude-obsidian 只有 `capture` 本地文件 + `adopt` 已有 vault，无 SaaS 导出解析） | ✅ |
| **内容洞察 L2/L3** | 空（`wiki-lint` 只做结构卫生：dead links / orphans / metadata gaps） | ✅ 核心 |
| **CLAUDE.md 生成** | 空 | ✅ 核心 |
| Wrapped 呈现层 | GitHub / Claude Code usage 有，vault 层无（Obsidian 生态只到 Dataview 查询 + YourPulse 活跃度） | ✅ 形式已验证 |

### 2.3 R1 源码级验证（2026-08-13）

§2.1 的三条空位原本只来自一次 README 抓取。已 clone 源码逐条核实（`AgriciDaniel/claude-obsidian`，5.6MB / 156 个源文件），**三条全部成立，且比 README 呈现的更彻底**：

| 断言 | 源码证据 |
|---|---|
| **无内容洞察** | `kmeans` / `k-means` / `hdbscan` / `umap` / `sklearn` / `AgglomerativeClustering` / `topic model` / `lda` 在全部 `.py` 与 `.toml` 中**零命中**。`embedding` 仅出现在 `scripts/retrieve.py` + `rerank.py`，用途是**检索**：BM25 top-20 → 可选 cosine rerank top-5（依赖本机 Ollama，无 Ollama 则 no-op）。15 个命令中无一个是洞察类动词 |
| **不生成 CLAUDE.md** | `CLAUDE.md` 仅出现在 `claude_obsidian/package_validation.py`，用途是把它连同 `README.md` / `WIKI.md` / `docs/*.md` 一起做**自己仓库的文档措辞一致性校验**，与用户产物无关 |
| **无冷启动导入** | `notion` / `apple note` / `evernote` / `roam` / `logseq` 在全仓库**零命中** |

**额外发现（对定位有利）**：仓库**无 `pyproject.toml` / `setup.py` / `setup.cfg`**——它不是 pip 包，而是**脚本集合 + 15 个 Claude Code skill**。也就是说它的分发形态绑定 Claude Code 生态，受众天花板是 CC 用户。我们定的**独立 CLI 是不同赛道，不构成正面竞争**。而它能拿到 10.8k★ 恰好证明这个领域的市场热度。

### 2.2 产品形态差异

claude-obsidian 的命令表是 `init / adopt / migrate / capture / transaction / checkpoint / lint`——**没有一个动词是给人用的**。它是**基础设施**，服务"已经决定要长期维护知识库的人"。

我们是**一次性转化器**：跑一次，拿走两个产物，之后可以再也不用我们。零承诺——不改工作流、不迁移、不学新概念。这是最强的传播主张，也是不与 10.8k★ 正面竞争的唯一姿势。

**代价（已知且接受）**：一次性 = 无留存，star 涨得快但用户不回来。对"扩大 Agent 领域影响力"这个目标够用（影响力靠传播不靠留存）。留存钩子在**第二次门诊**（系统复盘 / 持续体检），那天然需要"已经用了一段时间"，不在 v0.1 范围。

## 3. 已验证的地面真值

跑在贾老师真实语料上的实测（2026-08-13，脚本存于 `probes/kb_doctor_probe.py`，可重跑复现）：

| 样本 | 数字 |
|---|---|
| Notion 原始导出 | 1925 篇 md，**1149 篇 <200 字节（60% 是空壳）**，目录深 11–15 层 |
| Apple Notes 原始 | 620 篇，**249 篇空壳（40%）** |
| 处理后进 Personal/ | **242 篇（620 → 242，留存 39%）** |
| 已维护的 Wiki（优等生对照） | 466 篇，孤儿率 30%，断链 238 处（11%），无 frontmatter 12%，残桩率 **0%** |

**三条从实测中得到的硬结论：**

1. **mtime 完全不可信。** 优等生 Wiki 的"陈旧率 >180 天"算出来是 0%，不是因为勤快，是 Obsidian sync / git / 批量操作会刷新 mtime。所有人第一反应会用的新鲜度代理是坏的。→ 见 §5.1 新鲜度降级链。
2. **优等生语料校准不出真实阈值。** 残桩率在维护过的 Wiki 里是 0%，在原始 Notion 里是 60%。判据必须在**烂语料**上校准，`notion-export/` 和 `Archive/Apple Notes` 就是那份烂语料，已在手。
3. **"扔掉多少"本身就是产品的证明。** `620 → 242` 比任何功能描述都有说服力。

## 4. 架构

```
kb-init ~/notion-export/

 [1] 归一    调现成转换器 → 统一记录，分配稳定 doc_id
 [2] 清洗    标记 kept / dropped + reason（不真删记录）
 [3] 落盘    knowledge/*.md   标准 Markdown，**路径在此冻结**
 [4] 索引    分块 → 本地 embedding → 聚类 → 主题轴 + 时间轴     无需 API key
             （仅服务于洞察计算，非面向用户的检索功能——见 Non-goals）
 [5] 洞察    L2 轨迹（本地）/ L3 耦合（用户自己的 key）
             每条洞察强制挂 doc_id 做证据
 [6] 渲染    ├→ insights.json   不可编辑真源
             ├→ insights.md     操作层：带可见 ID，用户只改 [x]
             └→ report.html     呈现层：人看 · 可分享 · allowlist 脱敏
 [7] 编译    kb-init compile → CLAUDE.md    只收勾选项，正文从 json 取
```

**⚠️ 落盘（原第 7 步）已提前到第 3 步。** 原顺序有硬 bug：渲染出的证据链接指向 `knowledge/*.md`，而那些文件当时还没命名，链接必然指向不存在的路径。**输出路径必须在生成任何证据引用之前冻结。**

这七步不是直线，是**有回边的 DAG**——清洗、聚类、人工确认之间需要稳定身份，见 §4.3。

### 4.1 双输出与裁决权

两个输出共享同一份中间产物，但**要求会打架**，三处：

| | CLAUDE.md（档案线） | report.html（Wrapped 线） |
|---|---|---|
| 筛选方向 | 要**众数**：高频、稳定、可复用 | 要**离群点**：异常才有趣 |
| 出错代价 | agent 从此带着错误自我认知，隐性难察觉 | 一句话不准，笑一下算了 |
| 隐私边界 | 越私密越准，自用 | 必须能脱敏，要发出去 |

**裁决权归档案线**（按不可逆性定优先级：档案错了伤害持续且难察觉，Wrapped 少一条洞察伤害为零）。

### 4.2 Wrapped 是档案的验收界面

这不是两个并列输出，是 **生成 → 验收** 的闭环：

```
中间知识表示
   ├→ [Wrapped 渲染] → 人看 → 逐条确认/否决
   └→ [档案渲染] ←──────────┘  只收人确认过的
```

它解掉 L3 最大的风险（洞察会瞎编）：人肉 gate 是唯一可靠解法，而人凭什么愿意逐条校对一份枯燥配置文件？**因为它被渲染成了一份关于自己的、好玩的报告。**

实现上**不需要任何 JS 或服务**：`report.html` 只管好看；真正的确认动作发生在 `insights.md`——纯文本 checklist，用户用任何编辑器取消勾选，再跑 `compile`。

两者是**同一个验收界面的呈现层与操作层**，不是两个界面——产品上必须这样表述，否则会做成两个割裂的东西。

**但数据真源不能是展示层**（否则用户手改必然改坏格式，而且是静默改坏）：

- `insights.json` — 不可编辑真源，含 `run_id / corpus_hash / schema_version / insight_id / evidence_ids / canonical_text`
- `insights.md` — 每条带**可见的**短 ID（不用隐藏技巧，看得见反而不容易误改），用户**只应改 `[x]` 状态**
- `compile` 按 ID 从 json 取正文，**不信任用户修改后的文案**
- 遇到缺失 / 重复 / 未知 ID / 跨 run 或跨 corpus → **fail closed**，报出具体行号，**绝不静默少编几条**
- `kb-init validate insights.md` 独立可跑，`compile` 先自动调用

**洞察条数硬上限 12–20 条。** 超过这个量，人肉 gate 即使格式不坏，也会因校对疲劳而失效——这是产品约束不是技术约束。

> 设计克制说明：我们有过"拒绝给还没发生的流程提前建状态机"的教训（机制性预设 = jail）。此处仍加机制，是因为"用户手改文本会改坏格式"是**确定会发生**的，且静默少编几条的代价远大于报错。判据是"痛点是否已确定存在"，不是"机制是否复杂"。

### 4.3 中间表示（IR）合同 — 开工前必须先定

**这是 Codex review 判定的头号架构风险**：最可能让项目失败的不是 embedding 精度，而是清洗、重命名、聚类、人工确认之间**没有稳定身份和版本边界**。

- **稳定 `doc_id` 在第 1 步就分配**，记录原始路径、内容 hash、日期来源、最终输出路径。拍平和去重只改变**状态**，不抹掉来源
- **清洗是标记不是删除**：`kept / dropped + reason`。真删了，"620 → 242"这个我们最重要的数字就丢了，证据追踪也断了
- **输出路径在第 3 步冻结**，任何证据引用只能在此之后生成
- **分块映射持久化**：`doc_id → chunk_id`（因 §7 的 512 token 上限，必须分块）
- **manifest 记录可复现性三要素**：聚类算法 + 随机种子 + 模型版本 + corpus_hash
- **每步 checkpoint**，任一步失败不使前序产物报废
- **输出到新目录 + 原子落盘，默认不覆盖已有 `CLAUDE.md`**

## 5. 洞察分层

### L1 统计（不做主角）
主题分布 / 时间分布 / 来源分布。人人能做，零差异化。只作为报告的背景板。

### L2 轨迹（本地，无 key）

> ⚠️ **三类时间轴洞察（兴趣迁移曲线 / 半衰期 / 沉默主题）受日期覆盖率条件门约束。**
> 实测导出类语料的日期可解析率只有 5–6%（根因是导出包里就没有，详见 2A spec §2.2），
> 低于阈值时索引层置 `time_axis.available=false`，这三类洞察自动不产出。
> 四类里只有「留存率」不依赖时间轴。**这条直接改变了 L2 的重心：在目标语料上，
> L2 的主体是主题而不是轨迹。**

- **兴趣迁移曲线** — 主题簇在时间轴上的重心漂移。人对自己兴趣的漂移基本无意识
- **半衰期** — 每个主题簇的时间跨度与集中度：反复回来的是真兴趣，一阵风的是当时的噪音
- **沉默主题** — 曾经高频、近期归零
- **留存率** — 清洗前后的数字（见 §3 第 3 条）

### L3 耦合（需 LLM，用户自己的 key）
这一层是护城河所在——**非结构化→结构化是 LLM 独占地带，软件占位浅**。

- **知识断层** — 簇 A 与簇 C 语义相邻但中间无文档："你以为你懂，中间缺一块"
- **未兑现的意图** — 大量输入型文档（收藏/摘录）+ 零输出型文档的主题："你收藏了 40 篇讲 X 的，从没写过 X"。**杀伤力最强**，揭示意图与行动的落差
- **自称 vs 实际** — 显式声明类文档（目标/简介）与实际分布的偏差
- **矛盾对** — 观点相反且用户自己没意识到的文档对

**L3 硬约束：**

1. **每条洞察必须挂 `doc_id` 做证据，无证据不输出。** 一条错误论断会让整份报告可信度归零。这套 claim 级核验在 `giasip-research` 的 Claim Ledger 已跑通，直接迁移，非新发明。
2. **绝不遍历所有文档对。** 1925 篇 ≈ 185 万对，分块后更大。必须先用 kNN / 簇代表生成**少量候选**，再把**有数量上限**的候选交给 LLM。
3. **L3 失败不得使已完成的产物报废。** 每步 checkpoint——API 挂了，清洗结果和 L1/L2 洞察必须还在。

### 5.1 新鲜度降级链（因 mtime 不可信）

按优先级取第一个可得的：
1. frontmatter `created` / `date`
2. 正文中的日期
3. 文件名中的日期
4. `git log` 首次提交时间（若在 repo 内）
5. 均无 → 标记 `unknown`，**不猜**，且该文档不参与时间轴类洞察

## 6. CLAUDE.md 产出什么

不是笔记摘要，是**agent 用得上的东西**。1925 篇压成几千 token 是 1000:1 压缩比，选择标准是"稳定可复用"而非"频率高"：

- **关注领域** — 按稳定性排序（跨时间反复出现），不是按数量
- **领域词汇表** — 用户惯用的术语，让 agent 用他的语言跟他说话
- **判断偏好** — 从反复出现的取舍模式中提取
- **已知盲区** — 来自 L3 的知识断层
- **明确排除项** — 试过并放弃的方向（防 agent 反复推荐）

## 7. 关键技术决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 载体 | **独立 CLI**，非 Claude Code plugin | "谁都可以用"；CC plugin 的天花板是 CC 用户，而目标受众恰恰是还没入门的人 |
| Obsidian | **不依赖**。可选增益 | 三个产物（html / CLAUDE.md / *.md）没有一个需要它 |
| 链接语法 | **默认标准 `[标题](path.md)`**，`--wikilinks` flag 给 Obsidian 用户 | `[[wikilink]]` 是 Obsidian/Roam 方言非标准 Markdown，默认用它等于隐性绑定，在 VS Code 里全是死链 |
| 输入 | **导出文件夹/zip**，不做 OAuth 连接器 | N 个 OAuth 塌缩成 1 个解析层；不碰账号 = 全本地 = 隐私可讲，对企业尤其 |
| 解析 | **复用现成转换器**，不自己写 | 红海且成熟（§2.1）；自写是无底洞且零传播力 |
| 产出形态 | **静态文件，不是服务** | 静态文件能直接发给别人看——而"能发给别人看"正是传播的定义 |
| L1/L2 | 纯本地，无需 key | 免费预览层，隐私。**清洗秒出；索引首次运行需下载 ~90MB 模型并按分钟计**——原先写的「秒出」只对清洗成立，对索引不成立，`--no-index` 保留纯秒出通道 |
| L3 | 用户自己的 key | 不是阉割，是隐私与成本的诚实划分 |
| 语言/分发 | **✅ 已裁决：Python 3.12 + uv（`uvx kb-init`）** | FastEmbed + ONNX 是 R2 最稳方案且原生 Python，没必要为分发便利重造推理层；uv 在缺 Python 时能自动下载。**Node+npx 并无"真零安装"优势——它同样要求预装 Node** |
| 本地 embedding | **✅ 已裁决并于 2026-08-14 通过真实语料验收：FastEmbed + `BAAI/bge-small-zh-v1.5`**（512 维 / ~90MB / ONNX CPU / 无需 GPU）<br>`model2vec`（potion-multilingual）降为 `--fast` 预览档；多语言 fallback 更正为 `paraphrase-multilingual-MiniLM-L12-v2`（0.22GB，无前缀契约）——~~`multilingual-e5-small`~~ **不在 FastEmbed 支持列表里**，e5 家族只有 2.24GB 的 large 版且前缀需手动加 | 中文原生训练、体积可接受、工程风险最低。验收结论见 R2 |
| 分块 | **强制**。先分块 embedding 再聚合成文档向量 | bge 上限 512 token，不分块 → 长笔记**静默截断**，benchmark 再好也没意义 |
| 脱敏 | **双产物** `report.private.html` / `report.share.html`；共享版走**字段 allowlist** | 「默认脱敏 + PII 正则」制造虚假安全感。blocklist 永远补不完，allowlist 一次收敛——与我们在 headless 权限上学到的教训同构 |

## 8. Non-goals（明确不做）

- ❌ 不做 KB 维护管线（ingest / lint / compile 循环）— claude-obsidian 已占且更完整
- ❌ 不做检索层（BM25 / rerank / semantic search）— 同上
- ❌ 不做 OAuth 连接器（Notion API / flomo API / 得到 API）
- ❌ 不做 web 服务、不做账号体系、不做云端存储
- ❌ 不做持续体检 / 系统复盘 — 那是第二次门诊，需要"已用一段时间"，不在 v0.1
- ❌ 不做词云类装饰性可视化

## 11. 实现后的修订（2026-08-13 阻断项修复轮）

Codex 全分支终审推翻了 §4 的一个核心假设，记录在此避免重蹈：

**「把落盘提前到第 3 步」并不等于「路径已冻结」。** 提前的只是文件写入；链接改写仍在
逐篇进行，改写发生时目标文档还没命名，所以产出的链接大面积指向不存在的路径。
正确做法是**两遍式**：第一遍为全部 kept 文档冻结路径并建立引用映射，第二遍才改写落盘。

**测试体系的盲点**：`test_every_kept_doc_has_resolvable_out_path` 验的是 manifest 里
`out_relpath` 指向的文件存在，而从没有人验证**正文里的链接**指向的文件存在。七轮 review
全部落在同一个盲点上，直到跨阵营终审才捅破。

**合成语料测不出真实形态**：B1 修完后合成测试全绿，真实 Notion 语料却 288 条链接全死——
因为 Notion 用的是 URL 编码的标准相对链接（`[标题](Some%20Page%20abc.md)`）而非 wikilink。
**任何链接/路径类的改动，验收必须跑真实语料。**

新增的 manifest 字段：`unresolved_links`（退化为纯文本的链接账）、`skipped_inputs`
（因文件系统等价名被跳过的输入账）。两者都服务于同一条原则：**不静默丢东西**。

## 12. 链接解析语义的定案（2026-08-14，第 4–6 轮终审）

§11 之后又跑了三轮终审，每轮都在同一处抓到新的绕过路径。最终定下的不变量：

**绝不产出「活着的错链」。** 死链有人报，错链没人查——正文指向一篇不相干的文档，
而 manifest 显示解析成功。这条比"尽量多解析出链接"优先级高。

由此推出三条实现约束：

1. **两种引用语义各用一张索引，不能合并。** wikilink 是**名字**语义（Obsidian 按全库
   文件名解析，与目录无关）；标准 Markdown 链接是**路径**语义。混用一张表就会拿名字
   去解释路径。
2. **标准链接的基准只有一个：当前文档所在目录**（CommonMark）。不按 basename 跨目录
   兜底，也不"当前目录不中就换导出根再试"——根目录不是"另一个可以试试的基准"，
   它就是另一个目录。
3. **别名解析必须是三态**（命中 / 歧义 / 没有）。只回答"有没有命中"，歧义就会被下一层
   回退分支绕过：精确键 `foo.md` 判歧义作废后，剥成 `foo` 又唯一命中——而且因为解析
   成功了，歧义检查根本不会执行。

**贯穿三轮的教训**：每一条阻断都是「解析不到就再换一种猜法」的同一个变体。
只要还留着一条兜底路径，上面那条不变量就会被它绕过。**加兜底前先问它会不会指错。**

`--wikilinks` 由此重新定义：它只改**输出语法**，不跳过解析。目标一律先解析到冻结后的
输出名（`[[Project A]]` → `[[Project-A|Project A]]`，因为文件实际叫 `Project-A.md`），
歧义照样降级；只有"没有输出文件的目标"保留 `[[...]]`——那是 Obsidian 合法的未创建链接。

## 13. R2 验收结论（2026-08-14）

在 `Archive/Apple Notes` 清洗后的 287 篇上跑三模型 × 两方法对照。完整报告与簇样本在仓库外
（含个人语料内容，不进开源仓库）：`~/Documents/assistant-output/kb-init-r2/`。

| 模型 | 体积 | KMeans k=8 silhouette | HDBSCAN(mcs=5) 未归类 |
|---|---|---|---|
| **bge-small-zh-v1.5**（裁决保持） | 0.09 GB | **0.091** | 222/287 |
| jina-embeddings-v2-base-zh | 0.64 GB | 0.083 | 211/287 |
| paraphrase-multilingual-MiniLM-L12-v2 | 0.22 GB | 0.074 | 198/287 |

**结论：模型不是瓶颈。** 7× 体积换 3 个百分点的未归类率，且 KMeans 分数反而更低；以 R14
（首次运行下载已是体验风险）衡量，这个交换不成立。silhouette 全部落在 0.07–0.09 彼此拉不开，
**在这个任务上没有区分力**——验收只能靠人看簇，这正是当初写"不拿排行榜代替验收"的原因。

**真正的发现是聚类方法的分叉**：

- KMeans 强制每篇入簇 → 8–12 个簇里有 4–6 个能一眼认出（学生作业 / 排课 / 意大利语语法 /
  AI 项目 / 艺术家人物），其余 2–3 个是大杂烩——语料里本来零散的部分被摊进最近的簇。
- HDBSCAN 允许不归类 → 3 个极干净的主题，代价是 **69–77% 的笔记未归类**（三个模型一致）。

> **这里曾经写过一个更强的结论——"说明语料本身稀疏，不是模型缺陷"——它证据不足，已降级。**
> 站得住的只有弱版本：*在当前 400 字符分块与文档均值池化下，这三个模型之间的选择不是主要瓶颈*。
> 强版本还缺三项证据：① 三个模型共享同一套 mean pooling，若池化抹掉多主题或短片段信号，它们会
> **一起**失败；② 对三个表示空间用同一组 HDBSCAN 参数，不等于对每个空间都做过公平校准；
> ③ 人工看的一直是**已成形的簇**，从没随机抽查过 residual 文档能否重新组成主题。
>
> **最便宜的证伪实验（不必重跑 embedding，向量已缓存）**：随机抽 60 篇——40 篇三模型一致判为噪声、
> 20 篇模型间有分歧——隐藏原标签，人工只在"至少 3–4 篇能用一句话共同命名"时才组成一组。若那 40 篇
> 仍能组出多个清晰小组，则"语料天然稀疏"被证伪。再查这些人工同组文档的 top-5 邻居即可定位病灶：
> 邻居对但不成簇＝聚类参数问题；某个模型明显更差＝模型问题；三者邻居都错＝池化/表示问题；
> 人工也组不起来＝这才是对语料稀疏最直接的支持。

这条分叉直接关系 §4.2「Wrapped 是档案的验收界面」：若人要逐条确认洞察，**一条看不出是什么的
洞察比少一条洞察更伤**——原则倾向 HDBSCAN；但"70% 未归类"需要一个像样的说法（例如讲成
"碎片区：这些笔记还没长成主题"，本身即是一条洞察）。**留待 Plan 2 拍板。**
