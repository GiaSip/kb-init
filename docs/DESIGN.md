# kb-init — 设计文档 v0.1

> 工作名 `kb-init`。正式命名未定（开源项目名是营销决策，另行处理）。

## 1. 一句话

把你攒了几年、自己都没再打开过的笔记导出文件，一次性编译成**两样东西**：一份你会想转发的知识报告，和一份你的 AI agent 从今天起就能用的记忆文件。

## 2. 为什么是这个（定位）

### 2.1 三块无人占的位置

2026-08-13 检索确认（单次检索 + README fetch，**正式动手前需真装验证**）：

| 层 | 现状 | 我们 |
|---|---|---|
| 格式转换 Notion→md | 红海：notion2obsidian / Notion-to-Obsidian-Converter / notion_2_obsidan / notion-markdown-extractor | **不写，直接调** |
| KB 管线 ingest / lint / retrieve | `AgriciDaniel/claude-obsidian` 10.8k★ MIT v2.1.0，同源于 Karpathy LLM Wiki，且带 BM25 检索、事务回滚、CI | **不做** |
| **冷启动批量导入** | 空（claude-obsidian 只有 `capture` 本地文件 + `adopt` 已有 vault，无 SaaS 导出解析） | ✅ |
| **内容洞察 L2/L3** | 空（`wiki-lint` 只做结构卫生：dead links / orphans / metadata gaps） | ✅ 核心 |
| **CLAUDE.md 生成** | 空 | ✅ 核心 |
| Wrapped 呈现层 | GitHub / Claude Code usage 有，vault 层无（Obsidian 生态只到 Dataview 查询 + YourPulse 活跃度） | ✅ 形式已验证 |

### 2.2 产品形态差异

claude-obsidian 的命令表是 `init / adopt / migrate / capture / transaction / checkpoint / lint`——**没有一个动词是给人用的**。它是**基础设施**，服务"已经决定要长期维护知识库的人"。

我们是**一次性转化器**：跑一次，拿走两个产物，之后可以再也不用我们。零承诺——不改工作流、不迁移、不学新概念。这是最强的传播主张，也是不与 10.8k★ 正面竞争的唯一姿势。

**代价（已知且接受）**：一次性 = 无留存，star 涨得快但用户不回来。对"扩大 Agent 领域影响力"这个目标够用（影响力靠传播不靠留存）。留存钩子在**第二次门诊**（系统复盘 / 持续体检），那天然需要"已经用了一段时间"，不在 v0.1 范围。

## 3. 已验证的地面真值

跑在贾老师真实语料上的实测（2026-08-13，脚本存于 `probes/kb_doctor_probe.py`，可重跑复现）：

| 样本 | 数字 |
|---|---|
| Notion 原始导出 | 1925 篇 md，**1149 篇 <200 字节（60% 是空壳）**，目录深 11–15 层 |
| Apple Notes 原始 | 620 篇，**249 篇空壳（40%）** |
| 处理后进 Personal/ | **242 篇（620 → 242，留存 39%）** |
| 已维护的 Wiki（优等生对照） | 466 篇，孤儿率 30%，断链 238 处（11%），无 frontmatter 12%，残桩率 **0%** |

**三条从实测中得到的硬结论：**

1. **mtime 完全不可信。** 优等生 Wiki 的"陈旧率 >180 天"算出来是 0%，不是因为勤快，是 Obsidian sync / git / 批量操作会刷新 mtime。所有人第一反应会用的新鲜度代理是坏的。→ 见 §5.1 新鲜度降级链。
2. **优等生语料校准不出真实阈值。** 残桩率在维护过的 Wiki 里是 0%，在原始 Notion 里是 60%。判据必须在**烂语料**上校准，`notion-export/` 和 `Archive/Apple Notes` 就是那份烂语料，已在手。
3. **"扔掉多少"本身就是产品的证明。** `620 → 242` 比任何功能描述都有说服力。

## 4. 架构

```
kb-init ~/notion-export/

 [1] 归一    调现成转换器 → 统一记录 {title, body, created, path, source}
 [2] 清洗    扔掉空壳 / 去重 / 拍平深层目录
 [3] 索引    本地 embedding → 聚类 → 主题轴 + 时间轴          无需 API key
             （仅服务于洞察计算，非面向用户的检索功能——见 Non-goals）
 [4] 洞察    L2 轨迹（本地）/ L3 耦合（用户自己的 key）
             每条洞察强制挂具体文档做证据
 [5] 渲染    ├→ report.html    人看 · 可分享 · 默认脱敏
             └→ insights.md    每条前带 [x]，用户取消勾选不认可的
 [6] 编译    kb-init compile → CLAUDE.md    只收用户勾着的条目
 [7] 落盘    knowledge/*.md   标准 Markdown
```

### 4.1 双输出与裁决权

两个输出共享同一份中间产物，但**要求会打架**，三处：

| | CLAUDE.md（档案线） | report.html（Wrapped 线） |
|---|---|---|
| 筛选方向 | 要**众数**：高频、稳定、可复用 | 要**离群点**：异常才有趣 |
| 出错代价 | agent 从此带着错误自我认知，隐性难察觉 | 一句话不准，笑一下算了 |
| 隐私边界 | 越私密越准，自用 | 必须能脱敏，要发出去 |

**裁决权归档案线**（按不可逆性定优先级：档案错了伤害持续且难察觉，Wrapped 少一条洞察伤害为零）。

### 4.2 Wrapped 是档案的验收界面

这不是两个并列输出，是 **生成 → 验收** 的闭环：

```
中间知识表示
   ├→ [Wrapped 渲染] → 人看 → 逐条确认/否决
   └→ [档案渲染] ←──────────┘  只收人确认过的
```

它解掉 L3 最大的风险（洞察会瞎编）：人肉 gate 是唯一可靠解法，而人凭什么愿意逐条校对一份枯燥配置文件？**因为它被渲染成了一份关于自己的、好玩的报告。**

实现上**不需要任何 JS 或服务**：`report.html` 只管好看；真正的确认动作发生在 `insights.md`——纯文本 checklist，用户用任何编辑器取消勾选，再跑 `compile`。

## 5. 洞察分层

### L1 统计（不做主角）
主题分布 / 时间分布 / 来源分布。人人能做，零差异化。只作为报告的背景板。

### L2 轨迹（本地，无 key）
- **兴趣迁移曲线** — 主题簇在时间轴上的重心漂移。人对自己兴趣的漂移基本无意识
- **半衰期** — 每个主题簇的时间跨度与集中度：反复回来的是真兴趣，一阵风的是当时的噪音
- **沉默主题** — 曾经高频、近期归零
- **留存率** — 清洗前后的数字（见 §3 第 3 条）

### L3 耦合（需 LLM，用户自己的 key）
这一层是护城河所在——**非结构化→结构化是 LLM 独占地带，软件占位浅**。

- **知识断层** — 簇 A 与簇 C 语义相邻但中间无文档："你以为你懂，中间缺一块"
- **未兑现的意图** — 大量输入型文档（收藏/摘录）+ 零输出型文档的主题："你收藏了 40 篇讲 X 的，从没写过 X"。**杀伤力最强**，揭示意图与行动的落差
- **自称 vs 实际** — 显式声明类文档（目标/简介）与实际分布的偏差
- **矛盾对** — 观点相反且用户自己没意识到的文档对

**L3 硬约束：每条洞察必须挂具体文档做证据，无证据不输出。** 一条错误论断会让整份报告可信度归零。这套 claim 级核验在 `giasip-research` 的 Claim Ledger 已跑通，直接迁移，非新发明。

### 5.1 新鲜度降级链（因 mtime 不可信）

按优先级取第一个可得的：
1. frontmatter `created` / `date`
2. 正文中的日期
3. 文件名中的日期
4. `git log` 首次提交时间（若在 repo 内）
5. 均无 → 标记 `unknown`，**不猜**，且该文档不参与时间轴类洞察

## 6. CLAUDE.md 产出什么

不是笔记摘要，是**agent 用得上的东西**。1925 篇压成几千 token 是 1000:1 压缩比，选择标准是"稳定可复用"而非"频率高"：

- **关注领域** — 按稳定性排序（跨时间反复出现），不是按数量
- **领域词汇表** — 用户惯用的术语，让 agent 用他的语言跟他说话
- **判断偏好** — 从反复出现的取舍模式中提取
- **已知盲区** — 来自 L3 的知识断层
- **明确排除项** — 试过并放弃的方向（防 agent 反复推荐）

## 7. 关键技术决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 载体 | **独立 CLI**，非 Claude Code plugin | "谁都可以用"；CC plugin 的天花板是 CC 用户，而目标受众恰恰是还没入门的人 |
| Obsidian | **不依赖**。可选增益 | 三个产物（html / CLAUDE.md / *.md）没有一个需要它 |
| 链接语法 | **默认标准 `[标题](path.md)`**，`--wikilinks` flag 给 Obsidian 用户 | `[[wikilink]]` 是 Obsidian/Roam 方言非标准 Markdown，默认用它等于隐性绑定，在 VS Code 里全是死链 |
| 输入 | **导出文件夹/zip**，不做 OAuth 连接器 | N 个 OAuth 塌缩成 1 个解析层；不碰账号 = 全本地 = 隐私可讲，对企业尤其 |
| 解析 | **复用现成转换器**，不自己写 | 红海且成熟（§2.1）；自写是无底洞且零传播力 |
| 产出形态 | **静态文件，不是服务** | 静态文件能直接发给别人看——而"能发给别人看"正是传播的定义 |
| L1/L2 | 纯本地，无需 key | 免费预览层，秒出，隐私 |
| L3 | 用户自己的 key | 不是阉割，是隐私与成本的诚实划分 |
| 语言/分发 | **Python + uv（`uvx kb-init`）** — 待 review | 本地 embedding 生态（fastembed / model2vec）与解析生态均优于 Node；uvx 零安装体验已接近 npx |
| 脱敏 | report.html **默认脱敏**，`--no-redact` 关闭 | 报告里蹦出真实客户名，这份报告就发不出去了 |

## 8. Non-goals（明确不做）

- ❌ 不做 KB 维护管线（ingest / lint / compile 循环）— claude-obsidian 已占且更完整
- ❌ 不做检索层（BM25 / rerank / semantic search）— 同上
- ❌ 不做 OAuth 连接器（Notion API / flomo API / 得到 API）
- ❌ 不做 web 服务、不做账号体系、不做云端存储
- ❌ 不做持续体检 / 系统复盘 — 那是第二次门诊，需要"已用一段时间"，不在 v0.1
- ❌ 不做词云类装饰性可视化

## 10. 验收标准（v0.1 完成的定义）

在 `~/Documents/notion-export/`（1925 篇、60% 空壳）上跑一次，产出：

1. `report.html` — 能双击打开、无需联网、已脱敏、看完想转发
2. `insights.md` — 每条洞察带证据链接与勾选框
3. `CLAUDE.md` — 只含勾选项，**≤ 200 行且 ≤ 5,000 token**（超出即判定压缩失败）
4. `knowledge/*.md` — 标准 Markdown，VS Code 中无死链
5. 全程无需安装 Obsidian，L1/L2 全程无需 API key

## 附：这份设计是怎么来的（决策溯源）

- **医生比喻的分工**（贾老师）：持续体检 = 系统复盘，前提是已用一段时间；**KB 初始化 = 建档**，零时刻就能跑，是唯一能给新用户的东西。完整线 = 建档 → 洞察 → 治疗 → 复诊，我们已有第 3、4 段，缺的正是前两段
- **从结构诊断转向内容洞察**（贾老师纠正）：容器诊断（"你书架很乱"）→ 焦虑 → 焦虑同样驱动关闭页面；内容洞察（"你这个人在想什么"）→ 自我发现 → 驱动炫耀。Spotify Wrapped 不说"你歌单很乱"
- **两个输出是同一件事**（贾老师）：同一中间产物两个渲染器，工程无强偏向 → 逼出了 §4.2 的验收闭环，比原先的"并列输出"完整得多
- **不依赖 Obsidian 的产品理由**（贾老师）：不能让用户为了用我们，先去装另一个东西
